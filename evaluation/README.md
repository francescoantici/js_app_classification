# Evaluation of Models for Job Application Classification

This folder contains reference scripts used to evaluate the models' capability in classifying a job's application from its job script. 

## Evaluation scripts

The `evaluation_scripts` folder contains 100 PBS/Slurm job scripts executing HPC workload. The scripts are generated by claude. The first 50 scripts are simple job scripts executing a single application, while the last 50 are more complex workflows executing multi-steps pipelines.
The `evaluation_scripts_labels.csv` contains the reference application labels generated by combining the claude description and manual inspection. 

## Evaluation

After selecting a series of models, each model is fed every job script from the `evaluation_scripts` folder independently, and asked to generate the label. The python scripts used to do so is the `app_extraction.py` in the root folder of this repository. 

### Evaluation metrics

The results of the inference with the various models are stored in `results`. The evaluation of the model is three-fold, and it considers three metrics: 

- **Syntax correctness**: Whether a label is syntactically correct and it makes sense on a natural language perspective. If the label is just symbols, parts of the original prompt or code, or something like "the user asked me to..." it is not considered syntactically correct.
- **Semantically correctness**: Whether a label is a coherent response to the task, regardless if it's correct for the specific script. If a label is too vague or unrelated to the task (e.g. script, hpc, workload, grass, job, etc) it is not conisdered semantically correct.
- **Validity**: Whether a label is a valid answer to the task, for the specific job script. A valid label must be both syntactically and semantically correct. 

### Results 

All the result files are manually inspected and the metrics are manually computed. Below are the results.

| Model | Syntax correctness % | Semantic correctness %  | Validity % | Notes |
| -------- | -------- | -------- | -------- | -------- |
| DeepSeek-V4-flash | 100% | 100%  | 97% | The model carries out the task very well, it requires significantly more GPU memory w.r.t. other models |
| GLM-4.7-FP8 | 100% | 95%  | 86% | The model is slow, avg inference time of 16 seconds, up to more than 1 minute |
| gpt-oss-20b | 94% | 93%  | 80% | The model tends to hallucinate a lot returning general hpc application regardless of the script (e.g. molecular dynamics in a different script) |
| qwen3-coder:30b | 100% | 91%  | 85% | The model tends to give too generic labels sometimes, e.g. hpc code |
| codellama:7b | 97% | 74%  | 69% | The model tends to give too generic labels often, e.g. hpc code, hpc, etc |
| Kimi-K2-Thinking | 28% | 25%  | 20% | The model is clearly not working well with defined constraints on the output format and parsing. Most of the time the response is just symbols, parts of the script, or "The user asked me to...". Using it from the webui would probably give better results |
